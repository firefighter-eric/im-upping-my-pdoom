# 解梗伴看导出末尾修复提案

**LLMV_002 · v001.0 预览验收未通过；本提案未执行视频重新导出。**

导出进程成功写入输入端的 9195 帧，但 FFmpeg overlay 的 `shortest=1` 按较短的原片图像结束，实际只编码了 9193 帧。原片 306.416667 秒，原音轨 306.480181 秒；预览图像 306.433333 秒，原 AAC 包仍完全相同。不能把这个预览登记为规格完整的成片。

修复只改变新版本的导出结束条件：`shortest=0`，末尾保持原片最后一帧；明确 `-frames:v` 为已计算的完整音轨目标帧数。在提升临时 MP4 为结果前核验实际帧数、尺寸、帧率、音画时长差和 AAC 包，一项不符就记录失败。原片、音轨、歌词、解读内容、排版、采样和编码质量保持已绑定值。

补丁见 [export-endpoint.patch](export-endpoint.patch)，便于审阅的未应用代码见 [exporter-proposed.mjs](exporter-proposed.mjs)。二者仅是提案，不能当作当前可执行版本。采用前须创建 `projects/anabology/versions/v001.1`，调整作品内新版本与 R001 生成 ID、重新冻结引用，不覆盖 v001.0。

已用独立色块视频和静音 AAC 做边界回归，未使用 LLMV 素材、不是正式视频重试：30fps 旧方式仅 15/17 帧，修复方式 17/17；60fps 旧方式仅 30/33 帧，修复方式 33/33。两种修复输出都保持完整 AAC 数据包，完整解码通过。见 [回归结果](regression-result.json)。

待用户明确授权后，新版本分别单次生成全长 1080p30 预览和 3840×2160/60fps 完整版，完成规格、完整解码、AAC、实际播放检查后登记 review。所有旧文件与失败记录保留；本提案不继承人类批准。

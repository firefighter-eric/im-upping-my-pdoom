# 音频、渲染与验收

## 音频准备

先固定原输入、哈希、采样率、声道、时长与流起始时间。分析可用 WAV／单声道副本，成片仍使用用户选择的完整原音轨；记录转换、重采样、PTS 和分析时钟映射。

| 数据 | 用途与边界 |
| --- | --- |
| 人声／鼓／贝斯／其他分轨 | 减少伴奏对歌词对齐的干扰，驱动不同视觉层；分离伪影需要听辨 |
| 已校对歌词的强制对齐 | 获取行／词／必要时音节的演唱时间；不能用自动转录替代歌词真值 |
| 独立 ASR | 交叉检查漏词、错词与疑似时段，不把另一份机器结果当人工确认 |
| beats／downbeats／tempo | 控制乐句、切镜和重复结构；变速、弱起、器乐空拍需要检查 |
| 分轨 RMS／onset／pitch／频段能量 | 控制亮度、冲击、线宽、轨迹或音高相关动作；按数据含义命名 |

适用时比较原混音、单声道、左右声道和主唱的对齐结果；先处理低置信度、重复词、长音、伴唱与段落边界。人工修正记录原时间、新时间、原因和证据，避免全曲随意平移。

本项目 v002 的已执行技术组合可作兼容性参考：Demucs htdemucs_ft 四分轨、mel-band-roformer 主唱分离、MMS_FA 与 WAV2VEC2_ASR_LARGE_LV60K_960H 对齐、MLX Whisper large-v3-turbo 交叉检查，以及节拍／重拍／起音／包络。此列表不是永久推荐版本；新制作根据语言、歌声、平台和可用模型选择，并记录实际版本与权重来源。模型和中间数据不进 Git。

禁止移植另一首歌的歌词时间、手工修正、音频偏移或分析 JSON。容器延迟与解码时钟必须对当前输入测量。

## 双锚点踩点编排与验收

时间踩点与节奏踩点都是制作要求，分开建表、分开验收：

| 要求 | 锚点 | 画面命中事件 |
| --- | --- | --- |
| 时间踩点 | 当前输入中实际唱出的句、词、关键音节及长音边界 | 词语高亮、语义物体出现、动作完成或意义反转 |
| 节奏踩点 | 当前输入的 beat、downbeat、鼓 onset、乐句边界 | 切镜、碰撞、运动峰值、闪光与章节变化 |

人声分离帮助定位演唱，强制对齐提供词级候选时间，节拍／起音分析提供音乐候选时间；自动结果需结合当前歌曲核对。弱起、切分、渐慢、重复词、伴唱和长音不要按固定 BPM 推算整曲。低置信区间保留标记，避免把数据精确到毫秒误称为实际听辨准确。

**统一时钟**：秒为时间单位，明确原音轨零点和流起始时间。记录 `t_audio = t_analysis + analysis_to_audio_offset_seconds` 与 `t_video = t_audio + audio_to_video_offset_seconds`；偏移根据当前文件测量，已确认无偏移时写 0，未知时写 null／TBD。不能通过随意平移整首歌来掩盖局部错位。

**事件时间表**：每句／每个器乐段标出使用的人声与音乐锚点（类型、ID、时间、置信度／证据），关键视觉事件写明锚点引用、主动偏移、动画开始／命中／结束时间和验收容差。`target_video_seconds = anchor_audio_seconds + audio_to_video_offset_seconds + intentional_offset_ms / 1000`，正偏移表示晚于锚点。需要蓄势的动作提前开始，让碰撞、落位、变色峰值或切镜本身命中目标；仅让动画开始在拍点上不等于视觉冲击踩点。

字幕全文可先出现并留够阅读时间，逐词强调跟随人声；关键词对应的动作优先保持语义同步，背景脉冲和次层冲击可以跟随鼓点。主唱与音乐锚点不重合时分别驱动不同层；确需选择一个锚点时在分镜说明取舍，不把全部文字、镜头和物体同步闪烁。

节奏编排应覆盖全曲：器乐段有呼吸与拍感，主歌留出阅读空间，预副歌逐步蓄势，高潮提高事件密度或尺度，重复副歌通过空间、材质和控制关系发展。长音、停顿和空拍可以使用停留、延迟释放或留白，无需每拍切镜。

**编码后检查**：按当前输出 fps 将事件映射到帧，在最终视频抽取关键锚点的前／命中／后帧，记录实际命中帧时间、相对目标的误差和是否符合版本约定。30fps 一帧约 33.3ms，60fps 一帧约 16.7ms；帧取整误差、自动对齐误差、主动创意偏移与容器时钟偏移分别记录，不能混为“允许误差”。抽样需覆盖各段落／每遍副歌以及弱起、长音等可疑位置。

正常速度有声连续播放，听辨字词高亮、语义动作、鼓点冲击和转场是否吻合，确认采样模糊没有让峰值变钝、歌词没有因切镜丢失阅读时间。数据和关键帧检查通过也不能替代听辨；工具只确认 audio 播放状态时，写技术播放通过、有声感知同步待审。时间踩点、节奏踩点、歌词覆盖和有声回放分别记录状态与证据，未确认项保持 pending；修改已绑定成片时新建制作版本。

## 确定性场景

场景是 `frame(t, variant, seed, data)` 的函数。使用固定种子、按时间求粒子状态和动画曲线；不依赖实时 delta、调用次数、累积状态或未固定随机数。字体、纹理、shader 完成准备后才标记 ready。

为不同歌曲保留版本内 scene 和 treatment，公共引擎只提供时间、字体、线条、材质、后期和导出。避免把歌词、概率数字、角色或私人路径写进共享工具。

运动模糊需要在一帧内多次采样；先在线性 HDR 空间平均，再做 bloom／色调映射／输出。抖动、颗粒和稳定噪声采用明确的帧种子，避免子样本跨帧引入双影或迫使采样数上涨。自适应采样应有误差准则与上限；不是每一帧都用最高采样数。

## 预览采样档

根据用户 2026-10-02 确认，离线预览视频默认 **1920×1080、30fps、固定 4 次时间采样**，适用于短样片或完整创意预览；不要自动开启 108／324 次的高质量档。用户明确指定的其他规格优先。完整预览保留完整原音轨，目标帧数为 `ceil(duration_seconds × 30)`；显式短样片记录其区间。正式成片默认原生 3840×2160、60fps，质量采样按成片版本单独设置。

对当前渲染接口，在可编辑的预览版本 manifest 中设置 `width: 1920`、`height: 1080`、`fps: 30` 和 `sampling: {mode: "fixed", samples: 4, shutter: 0.2}`，同步更新时长、目标帧数及依赖帧率的数据。其含义是同一最终帧计算 4 个时间子帧，输出帧率仍由 fps 决定。实时浏览器交互预览可沿用引擎的快速模式，区别于这里的离线预览导出。

记录实际采样设置和 preview 用途。完整预览应覆盖完整音轨，不能把一秒工具 smoke 当成创意预览。进入精修成片时另行选择固定次数或自适应档，先评估重镜头的质量与耗时；已绑定执行记录的版本通过新版本调整，不能中途改动正在渲染的参数。

## 原生 4K60

- 明确逻辑设计坐标与物理像素，render target／最终编码都为 3840×2160；1080p 画面放大不算原生 4K。
- Canvas 文字层、字形纹理、atlas、离屏画布按物理尺寸生成；只放大最终纹理会模糊。
- shader 中 `gl_FragCoord`／`fwidth` 是物理像素，线宽、抗锯齿羽化与设计坐标需正确换算。原生输出检查细线，不能只看缩小预览。
- bloom 核、降采样层级、噪声尺度和 HUD 需要一致的尺寸策略；必读字体保留清晰边缘。
- 60fps 是输出时间采样，不等于实时浏览器必须每秒完成 60 张离线画面。先在代表性重场景测出帧与编码成本，不套用作者的机器耗时。

导出可先用 JPEG 帧接口；吞吐需要时使用原始 RGBA、异步 GPU readback 和有确认／背压的 WebSocket → ffmpeg。排队数量受限，处理写入失败、ffmpeg 退出码和尾帧排空，不能静默丢帧。传输优化不应改变画面时间或跳过正式验收。

## 当前仓库接入

仅在 `im-upping-my-pdoom` 或确认兼容的仓库使用以下约定；其他仓库先读自己的接口和命令。

- `projects/<slug>/versions/<version>` 保存代码、数据、manifest、treatment、运行与来源记录；本仓库同一创意方向使用 v003.0／v003.1 等小版本，新创意方向递增主版本，历史 v001／v002 保持兼容。已交付／绑定运行的版本改创意或代码时新建版本。
- 等待 `window.ready` 完成；`window.renderFrame(seconds, variant)` 返回 JPEG base64。扩展 RGBA 传输按现有公共 render 接入。
- 帧数为 `ceil(duration_seconds × fps)`，完整音频与画面末尾差异小于一帧。显式分段样片记录其区间，不冒充整片。
- 用现有 `audio:prepare`／各阶段、`build:renderer`、`render:stills`、`render:smoke` 等命令；先读参数和运行状态。正式 render 单次执行，失败记证据后停止，不自动重试、修改参数或抢占他人任务。
- 预览为临时只读服务，随机端口；指定端口先查占用，不停止其他服务，不复用固定 5173。
- 公共 smoke 输出在忽略的 `.cache/`，只证明工具短片验收。
- 当前上传策略为代码、字体／图片、分析 JSON 与记录；音视频、模型、依赖、缓存和凭据忽略。LFS 属性存在不等于用户授权上传媒体。音乐／歌词权利 TBD 不能改写成代码许可。

## 两类验收

先审查关键样片；在已授权完整制作范围内通过后继续完成。采样仍发现视觉问题时修正 draft；遵守已绑定版本不可覆盖规则。

**技术验收**：核对实际尺寸、CFR／帧率、帧数、时长、音轨与 PTS，完整解码；播放时检查进度推进、媒体错误并跳转不同段。静音自动播放证明视频可播放，仍需有声听辨歌词同步、完整音轨与接缝。

本仓库源代码修改要求 `npm run check`、`npm test`、`npm run verify`。媒体完成后用 `verify:media -- --project <slug> --version <version>` 核验、按现有流程 register 为 review，并运行 `verify:playback` 加实际有声审看。CI 的 `verify:source` 不能证明本地媒体已经恢复或成片通过。

**视觉验收**：逐句覆盖、时间踩点、节奏踩点、正常速度可读性、场景语义、章节发展、转场、亮暗节奏和结尾；查看原生帧以检查字体／线条，再有声连续播放检查动作。技术通过而视觉待改时如实报告，不自动批准。

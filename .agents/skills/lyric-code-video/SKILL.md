# 歌词驱动代码音乐视频

把歌曲组织成有语义、有节奏、有视觉发展的作品。歌词既是叙事骨架，也是可进入场景的图形材料；每段画面应能回答“这句歌词在视觉上发生了什么”。

## 任务范围与起点

- 先识别用户要分析、方案、样片、修改还是完整制作；只执行已授权范围。已有完整制作授权时，样片用于内部校验，校验后继续完成，不另设批准关卡。
- 先读所在仓库的 AGENTS、项目定位、作品来源、当前版本 manifest、treatment、输入与权利记录。原片和既有候选帮助发现问题；源文件和已绑定执行记录的版本保持可追溯。
- 对本用户的新制作，默认原生 **3840×2160、60fps、TypeScript＋Three.js／WebGL**。明确的用户要求和版本规格优先；历史作品不因此改规格。视频的 fps 与显示器刷新率分开验证。
- **预览视频默认 1920×1080、30fps、固定 4 次时间采样**，用于快速审看创意、分镜和整片节奏；用户明确指定其他次数时服从其要求。高质量成片按该版本 manifest 执行，预览档与成片档分别记录，不改动正在运行或已绑定执行记录的版本参数。
- 默认完整保留选择的原音轨，不裁剪、变速或重写。用于分析的分轨不替换成片音轨，除非用户明确要求。
- 默认让**每一句唱出的歌词都在屏幕上可读**；可以逐词出现、变色、书写或进入物体。关键词强调不能替代整句覆盖。用户明确选择纯视觉作品时服从其选择。

## 从参考到制作

### 参考与视觉方案

研究审美或写分镜时，读 [视觉设计与评审](references/visual-direction.md)。分析具体原片时实际查看代表帧和连续镜头，记录时间、证据与观察范围；单帧不能证明转场，静音预览不能证明音画同步。

借鉴 pdoom-video 的设计或实现时，读 [参考项目与迁移边界](references/pdoom-reference.md)。同时研究原视频与固定提交的源码；源码后续修订可能与原片不同。提取设计机制，具体色彩、字体、隐喻与人物随新歌重新选择。

用 [分镜模板](assets/storyboard-template.yaml) 记录歌词、视觉事件、词级呈现、镜头、转场和证据。每一段至少明确一个主事件；重复副歌通过空间、尺度、材质或意义升级，保持可识别的视觉母题。先建立字体层级、调色板、材质和运动语法，再写场景。

### 音频数据与代码

制作或技术迁移时，读 [音频、渲染与验收](references/audio-rendering.md)。原音轨为统一时钟；人声分离、歌词强制对齐和节拍分析分别提供不同信息，不能互相替代。

维护完整歌词清单与词级时间，标记低置信度、多声部、重复词、长音和人工修正；听辨可疑位置。制作视觉事件时结合歌词语义、鼓起音、节拍／重拍与分轨特征，不把所有动作都机械吸附到拍点。

### 时间踩点与节奏踩点（制作必做）

- **时间踩点**：全文字幕、词级强调和歌词对应的语义动作对齐实际演唱的句／词／关键音节。字幕可以提前出现以保证阅读，但高亮和动作的命中时刻跟随人声；不能为了就近拍点把歌词动作移离演唱时间。
- **节奏踩点**：切镜、物体冲击、镜头运动峰值、灯光／材质变化和段落升级，根据当前歌曲的节拍、重拍、鼓起音与乐句安排。器乐段也需有节奏设计；快段、慢段、蓄势与高潮的视觉节奏应有变化。
- 分镜同时记录人声与音乐锚点、动画开始／命中／结束时间及主动偏移。不同视觉层可使用不同锚点；需要取舍时记录理由。具体方法见 [双锚点踩点编排与验收](references/audio-rendering.md#双锚点踩点编排与验收)。
- 在最终编码视频中检查关键事件的前／命中／后帧，并正常速度有声连续审看。静帧、波形、播放进度推进或未静音状态都不能单独证明踩点正确；没有实际听辨证据时保持同步验收 pending。

画面由时间、变体和固定种子确定；支持任意时刻取帧、倒序取帧与运动模糊采样。先检验代表性难镜头的构图、可读性、转换和原生分辨率性能，再执行整片。渲染失败遵循所在项目的停止规则，不自动重试或悄悄改参数。

### 交付

分别给出视觉审看与技术验收结果。构建成功、文件存在、4K60 或可播放都不足以证明作品审美达标。

- 视觉：逐句覆盖账本、时间踩点、节奏踩点与阅读时间分别验收；场景是否表达语义；重复段是否发展；是否有字被裁切、眩光、过暗、无意空帧或单调循环。
- 技术：实际分辨率、CFR 帧率、目标帧数、完整音轨、完整解码和播放／跳转；核查字体与画面在原生输出下正常。
- 记录实际工具／模型版本、提示词、参数、代码／输入／输出哈希、日期、运行状态和来源。未知事实和权利保持 TBD。
- 生成候选进入 review；只有人类明确批准才能记为 approved。技能调用本身不授权上传、PR、合并或对外发布。

最终交付应链接版本、方案、可用成片和验收记录，明确未完成项。仅分析时交付证据与修改建议；仅方案时交付可执行分镜，不冒充已渲染结果。
